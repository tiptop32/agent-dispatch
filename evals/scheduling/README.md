# Evals: планирование корневых задач и ревью

Детерминированный ин-process прогон планирования ёмкости демона. Живых CLI,
сети и демона не нужно: Dispatcher поднимается на гейт-адаптерах из
`harness.py`, задачи «зависают» на гейтах, сценарий отпускает их в заданном
порядке. Стоимость нулевая, результат воспроизводим (у стресс-гонки есть
`--seed`).

Запуск:

```bash
uv run python -m evals.scheduling                     # все сценарии, seed по умолчанию
uv run python -m evals.scheduling --seed 42           # другой расклад гонки
uv run python -m evals.scheduling --rounds 30         # длиннее стресс-гонка
```

Код возврата 0, если все инварианты сошлись; иначе 1 и перечисленные причины.
JSON-отчёт пишется в `evals/reports/scheduling-*.json`.

## Что проверяется

Поведенческие инварианты планировщика, не статические флаги конфига:

1. `review_unblocked_by_saturated_coding` — корневое ревью стартует, пока оба
   задачных слота заняты заблокированными задачами: у ревью собственная
   ёмкость (`server.max_concurrent_reviews`).
2. `limit_groups_under_global_ceiling` — два занятых слота группы codex не
   мешают стартовать opencode из другой группы; следующая задача ждёт общий
   потолок, а отмена ожидающей group-slot задачи не создаёт лишний слот.
3. `excess_reviews_queue_in_own_capacity` — лишнее ревью ждёт в ревью-ёмкости
   и не занимает слот задачи; после освобождения доделывается.
4. `cancellation_releases_capacity` — отмена заблокированной задачи
   освобождает задачный слот, отмена ревью — ревью-ёмкость, и только их.
5. `nested_work_bypasses_pools` — вложенная работа (hop > 0) идёт мимо всех
   пулов, иначе исполнитель ждал бы слот, занятый его же родителем.
6. `queue_fallback_equivalent_capacity` — переполнение занятой группы уходит
   в свободную группу того же тира после порога; отмена возвращает ёмкость,
   следующая задача снова выбирает preferred.
7. `stress_race_seed_<seed>` — гонка из `--rounds` перемешанных задач и ревью
   с частичными отменами: без голодания (каждая не отменённая задача
   завершается), без превышения пределов каждого пула и без утечек
   (семафоры восстановлены, cwd-локи и события задач убраны).

Негативные проверки («не стартовал») защищены гейтами: пока чужой гейт
держится, задача не может стартовать ни на какой скорости машины, поэтому
короткий таймаут ожидания не делает прогон флакующим.
