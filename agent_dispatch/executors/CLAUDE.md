# Адаптеры исполнителей

- omp, в котором модель не ответила ни разу (нет `text`, `toolCall`, `stopReason`; без изменений и без события ошибки), даёт `failed` с `omp: no model response` вместо `partial`, потому что такой запуск молча выходит без ответа модели.
- omp запускается со stdin=DEVNULL, потому что без TTY ждёт EOF и висит; корпоративные исполнители получают `--profile x5`, чтобы профиль и сабагенты оставались внутри периметра; все запуски получают `NODE_USE_SYSTEM_CA=1`, потому что корпоративный RootCA лежит в Keychain, а bun без флага ему не доверяет.
- Ключ балансера omp берётся через `apiKey: "!…"` и `omp-setup/bin/lb-key`, а `AGENT_LB_API_KEY` удаляется из env дочернего omp, потому что окружение запускающего процесса доходит до bash-агента.
- Продолжение использует id из первой строки `{"type":"session"}` через `--resume <session id>` в том же cwd, session-dir и профиле; omp не использует протоколы старых CLI.
