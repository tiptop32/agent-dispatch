# Workflow: ответственность исполнителя и вызывающего

AgentDispatch делит работу между исполнителем и вызывающим. Исполнитель вносит
изменение и проверяет затронутую область. Вызывающий независимо проверяет diff,
запускает итоговый общий gate и коммитит. У каждого действия один ответственный.

## Что проверяет код, а что решает модель

Код проверяет всё, что можно проверить механически: тесты, линтеры,
детерминированные evals и схему результата. Модель понимает задачу, меняет код и
проверяет diff. Для механической проверки доказательство — команда и её статус в
поле `tests`, а не пересказ результата.

## Какие проверки запускает исполнитель

Исполнитель запускает проверки для затронутой области: регрессионные тесты и
детерминированные evals, связанные с изменением. Общий прогон репозитория по
незатронутым модулям запускает вызывающий в итоговом gate.

Каждая проверка имеет одного ответственного. Исполнитель не повторяет зелёные
проверки, если изменение не могло повлиять на них. Платные evals
(`evals.routing`, `evals.smoke`) и итоговый протокол принадлежат вызывающему.

Изменение кода отменяет только связанные с ним результаты проверок. Остальные
зелёные результаты остаются в силе.

## Когда остановиться

Исполнитель останавливается, когда выполнил критерии приёмки. Он не запускает
дополнительные проверки «на всякий случай». Если остаётся риск, исполнитель
называет его в `summary` и указывает минимальную проверку, которая этот риск
закроет.

Выйти за затронутую область можно только из-за конкретного остаточного риска.
Это решение по задаче, а не правило «всегда прогонять всё».

## Почему Task Package остаётся компактным

Task Package и ответ исполнителя содержат только нужный контекст. Полные данные
передаются по запросу. Вызывающая модель перечитывает каждый байт контекста на
каждом ходе.

## Что остаётся в корневом pre-commit

Корневой pre-commit по-прежнему запускает полный gate: ruff, detect-secrets и
pytest. Его запускает вызывающий при коммите. Хук нельзя отключать или обходить
через `--no-verify`.

## Что измеряет offline workflow eval

`evals/workflow` строит настоящие `TaskPackage` через `build_task_package` и
передаёт их в `render_prompt`. Небольшой корпус покрывает task и review, все
адаптеры, три режима контекста и вложенный hop. Проверка сравнивает отдельные
секции готового промпта с контрактами ответственности, запрета commit/push и
review только для чтения:

```bash
uv run python -m evals.workflow
```

Этот offline eval не запускает LLM и не доказывает, что исполнитель выполнит
инструкции. Он доказывает только то, что AgentDispatch добавил нужные инструкции
в итоговый промпт. Поведение локального агента проверяет платный smoke-прогон вне
этого eval: `uv run python -m evals.smoke`.
