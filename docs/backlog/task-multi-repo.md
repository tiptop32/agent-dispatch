# /task на несколько реп: один тикет, по worktree на каждую репу

Отложено 2026-11-15: такие тикеты бывают редко. План `/task` (docs/plans/20261115-task-entry.md)
сразу хранит `repos` списком, поэтому позже миграция состояния не понадобится.

Дизайн из брейншторма: в PLAN у каждой задачи есть `repo:`, список реп подтверждается на
чекпоинте 1, worktree создаются после этого, ветка `<id>-<slug>` одна для всех реп.
plan-dispatch передаёт `cwd` нужного worktree (`_cwd_lock` уже ключуется корнем рабочей
копии, параллельность есть). `task diff` склеивает дифы всех реп для чекпоинта 2.
MR заводится на каждую репу со ссылками на соседние, порядок мержа берётся из зависимостей
плана, `cleanup` чистит только смерженные. Тесты: N реп в состоянии, разбор `repo:` и ошибка
до создания worktree, склейка дифа, порядок мержа, частичный cleanup.
