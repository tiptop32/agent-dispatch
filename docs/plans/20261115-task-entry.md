# Точка входа `/task` (задачи 4 и 5 из 20261115-sadensmol-adoption.md)

## Почему

Сейчас kaiten, wt, planning:make, plan-dispatch и gitlab-mr пользователь соединяет
руками, и каждый переход стоит ему сообщения. Цель такая же, как у sadensmol: человек
нужен в трёх местах (план, диф, критичное решение), остальное агент делает сам.

## Метрика

Число сообщений пользователя на задачу от `new` до MR, считает `extract.py` из retro.
Цель около 3. Базовую линию снять на 3 задачах до внедрения.

## Поток

`new <kaiten-id|url|"текст">` → kaiten (только для id/url) → `wt`: worktree и ветка
`<id>-<slug>` → `stage set plan` → `planning:make` с контекстом карточки →
**чекпоинт 1** (webrev плана) → `stage set exec` → `plan-dispatch` → docs-шаг →
`decision open` (**чекпоинт 3**, если есть записи) → **чекпоинт 2** (plannotator-review
дифа) → `gitlab-mr` → `cleanup` после мержа.

Если текст свободный, id задачи это slug, а шаг kaiten пропускается.
